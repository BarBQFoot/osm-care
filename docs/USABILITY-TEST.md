# My OSM — Usability Test Plan

## วัตถุประสงค์

ตรวจว่าผู้สูงอายุที่ไม่ถนัดเว็บไซต์สามารถเข้าใจหน้าแรก ค้นหาบ้าน เปิดรายชื่อสมาชิก เพิ่ม/แก้ไขข้อมูล และพิมพ์เอกสารได้ด้วยตนเองตาม UX proposal ใน `SENIOR-UX-GUIDELINES.md`

## ผู้เข้าร่วม

- รอบ formative: ผู้สูงอายุ 5 คน อายุประมาณ 60 ปีขึ้นไป ใช้สมาร์ตโฟน/คอมพิวเตอร์ไม่คล่อง
- ถ้าเป็นไปได้รวมผู้ใช้แว่นสายตา/การมองเห็นลดลง และผู้ใช้โทรศัพท์จอเล็ก
- ใช้ข้อมูลสังเคราะห์เท่านั้น ห้ามกรอกเลขบัตรประชาชน เบอร์ หรือข้อมูลสุขภาพจริง
- ขอความยินยอมก่อนบันทึกเสียง/ภาพ; จดผลแบบไม่ระบุตัวบุคคล

## สภาพแวดล้อมและอุปกรณ์

- Prototype Angular บนโทรศัพท์จอ 6 นิ้วและ Laptop/Tablet
- ใช้ browser zoom 100% แล้วทดสอบ 200%; รอบ keyboard-only เพิ่มบน Desktop
- ตั้งค่า font scale และความสว่างให้เหมาะกับผู้เข้าร่วม ไม่ช่วยชี้ปุ่มระหว่างภารกิจ

## บทนำสำหรับผู้เข้าร่วม

“เรากำลังทดสอบหน้าจอ ไม่ได้ทดสอบตัวคุณ ใช้ตามที่คุณคิดได้เลย ถ้าติดขัดพูดออกมาว่ากำลังมองหาอะไร เราจะไม่บอกคำตอบระหว่างทำ เว้นแต่คุณขอหยุด”

## ภารกิจ

1. **เริ่มต้น:** เปิดหน้าเว็บและบอกว่าหน้านี้ใช้ทำอะไร แล้วหาทางไปยังข้อมูลครัวเรือน
2. **ค้นหา:** ค้นหาบ้านเลขที่ `12/1` แล้วเปิดดูรายชื่อสมาชิกในบ้าน
3. **เพิ่ม:** เพิ่มครัวเรือนใหม่ด้วยบ้านเลขที่ `88/2` และรหัส `ชุมชน-011`
4. **แก้ไข:** แก้เบอร์โทรตัวอย่างของสมาชิก แล้วบันทึก; ผู้ดำเนินการต้องยืนยันให้ใช้เฉพาะข้อมูลสมมติ
5. **พิมพ์:** เปิดหน้าพิมพ์ เลือกครัวเรือนหนึ่งหลัง ตรวจตัวอย่าง A4 และกดปุ่มพิมพ์จนถึง print preview (ไม่ส่งเครื่องพิมพ์จริง)
6. **ป้องกันความผิดพลาด:** เริ่มกรอกฟอร์มแล้วกดกลับโดยไม่บันทึก; ตรวจว่าผู้ใช้เข้าใจคำถามยืนยันและเลือกยกเลิกการออกได้

## วิธีเก็บผล

- สำเร็จเอง / สำเร็จหลัง hint / ไม่สำเร็จ
- เวลาโดยประมาณต่อภารกิจ, จำนวนครั้งกดผิด, จุดลังเล/ย้อนกลับ และคำพูดที่สะท้อนความเข้าใจ
- ความมั่นใจหลังแต่ละงานให้คะแนน 1–5 และถาม “ส่วนไหนทำให้ไม่แน่ใจ”
- อย่าตีความการพูดออกเสียงว่าเป็นความผิดพลาด; สังเกตการกระทำและถามภายหลัง

## เกณฑ์ผ่านรอบแรก

- อย่างน้อย 4 ใน 5 คนทำภารกิจ 1–5 สำเร็จโดยไม่รับ hint
- ทุกคนพบปุ่มกลับและยกเลิกได้โดยไม่สูญเสียข้อมูลโดยไม่ตั้งใจ
- ไม่มีการกดลบข้อมูลตัวอย่างโดยเข้าใจว่าเป็นปุ่มบันทึก
- ไม่มีจุดสำคัญถูกตัดเมื่อ zoom 200% หรือหน้าจอ 320px
- ปัญหา critical/high ทุกข้อมีแนวทางแก้ก่อนเริ่มรอบทดสอบถัดไป

เกณฑ์นี้เป็นเกณฑ์ภายในสำหรับ prototype ไม่ใช่หลักฐานรับรอง WCAG หรือ usability สำหรับผู้สูงอายุทุกกลุ่ม

## ผลลัพธ์หลังทดสอบ

บันทึกตาราง Issue / ผู้ได้รับผล / ความรุนแรง / หลักฐานสังเกต / การแก้ / สถานะ แล้ววนทดสอบซ้ำเฉพาะ flow ที่แก้ ห้ามใส่ข้อมูลส่วนบุคคลจริงในรายงาน
