# My OSM — UX Guidelines สำหรับผู้สูงอายุ

## เป้าหมายผู้ใช้

ผู้ใช้หลักคือ อสม. 1 คน ดูแลประมาณ 10 ครัวเรือน อาจไม่คุ้นกับมือถือและเว็บไซต์ จึงต้องอ่านป้ายแล้วเข้าใจได้ทันที ใช้ปุ่มที่เห็นชัด และย้อนกลับได้โดยไม่หลงทาง

## แนวทางประสบการณ์

- **หนึ่งหน้ามีงานหลักหนึ่งอย่าง** ใช้หัวข้อบอกว่ากำลังทำอะไร และมีปุ่มหลักที่เห็นได้โดยไม่ต้องค้นหา
- **ใช้คำคุ้นเคย** เช่น “หน้าหลัก”, “ครัวเรือน”, “สมาชิก”, “บันทึกข้อมูล”; หลีกเลี่ยงศัพท์อังกฤษในข้อความบนหน้าจอ
- **ทุกหน้ามีทางกลับ** หน้าในรายละเอียดและฟอร์มแสดงปุ่ม “กลับ” หรือ breadcrumb ที่มองเห็นและกดได้สะดวก
- **ยืนยันก่อนการกระทำที่ย้อนคืนยาก** แจ้งว่าจะลบอะไรและผลต่อข้อมูลในบ้านนั้น ใช้ปุ่ม “ยกเลิก” และ “ยืนยันการลบ” ที่แยกจากกันชัดเจน
- **แสดงผลการกระทำ** หลังบันทึกให้มีข้อความ “บันทึกข้อมูลแล้ว” พร้อมปลายทางที่เข้าใจได้; เมื่อผิดพลาดให้คงค่าที่กรอกไว้
- **ช่วยโดยไม่กล่าวโทษ** ใช้คำแนะนำเช่น “กรุณากรอกบ้านเลขที่ เช่น 12/1” แทนข้อความเชิงเทคนิค
- **อย่าซ่อนความสามารถไว้หลัง gesture** ทุกงานทำได้ด้วยปุ่มหรือลิงก์ที่มองเห็น

## โครงหน้าหลักที่เสนอ

### ภาพรวม

1. แถบด้านบนมีชื่อ My OSM และตัวเลือกเปิดเมนูบนมือถือ
2. ข้อความต้อนรับและวันที่เป็นข้อมูลประกอบ ไม่แย่งความสนใจ
3. ปุ่มใหญ่ “ค้นหาครัวเรือน” หรือช่องค้นหาที่เด่น และปุ่ม “เพิ่มครัวเรือน”
4. สรุปจำนวนบ้าน/สมาชิกเป็นข้อความขนาดใหญ่
5. รายการครัวเรือนล่าสุดเป็นทางลัด ไม่ใช้กราฟที่ต้องตีความ

### รายการครัวเรือน

- ชื่อหน้า “ครัวเรือน” พร้อมคำแนะนำ “พิมพ์บ้านเลขที่หรือรหัสครัวเรือนเพื่อค้นหา”
- ช่องค้นหาสูงอย่างน้อย 56px และมีปุ่มล้างคำค้นที่มีป้ายกำกับ
- แต่ละรายการแสดง “บ้านเลขที่”, “รหัสครัวเรือน” และ “สมาชิก X คน”; แถวทั้งแถวกดเปิดรายละเอียดได้
- สถานะไม่พบรายการบอกวิธีแก้ เช่น ล้างคำค้น หรือกลับไปดูทั้งหมด

### รายละเอียดครัวเรือนและสมาชิก

- แสดงปุ่ม “กลับไปหน้าครัวเรือน” ไว้ด้านบนอย่างชัดเจน
- แสดงบ้านเลขที่และรหัสบ้านเป็นหัวใจของหน้า; สมาชิกอยู่ในส่วนถัดไป
- ปุ่ม “เพิ่มสมาชิก” และ “แก้ไขข้อมูลบ้าน” มีข้อความเต็ม ไม่ใช้ไอคอนอย่างเดียว
- การลบบ้านระบุว่าจะลบข้อมูลบ้านและสมาชิกที่เกี่ยวข้องตามกติกาที่ผู้ใช้ยืนยัน

### แบบฟอร์ม

- แบ่ง “ข้อมูลครัวเรือน”, “ข้อมูลบุคคล” และ “ข้อมูลติดต่อ” ออกจากกัน
- label อยู่เหนือช่องกรอก; ตัวอย่างอยู่ใน helper text หรือ placeholder ที่ไม่แทน label
- ฟิลด์ที่จำเป็นมีคำว่า “จำเป็น” หรือเครื่องหมายพร้อมคำอธิบาย
- ปุ่มบันทึกและยกเลิกอยู่ท้ายฟอร์ม; บนมือถือสามารถทำ action bar ที่ไม่บังเนื้อหา
- เมื่อเปลี่ยนค่าจากเดิมแล้วกดกลับ ให้ถามว่าจะออกโดยไม่บันทึกหรือไม่
- ระหว่างบันทึก ปุ่มหลักแสดง “กำลังบันทึก…” และปิดการส่งซ้ำ; เมื่อเสร็จแสดงข้อความยืนยัน

### พิมพ์เอกสาร

- ใช้ชื่อชัด “พิมพ์เอกสาร” และปุ่ม “พิมพ์เอกสาร A4”
- แสดงขอบเขตที่จะพิมพ์และตัวอย่างหน้ากระดาษก่อนเปิด print dialog
- ปุ่มกลับมองเห็นชัด; การพิมพ์ไม่เปลี่ยนข้อมูล

## ข้อกำหนด responsive

- Desktop/Tablet: ใช้เมนูหลักคงตำแหน่งและรายการที่อ่านง่าย
- Mobile: เมนูหลักเปิดด้วยปุ่ม “เมนู”; เมื่อเปิดให้เห็นชื่อเมนูและกดปิดได้ง่าย
- ที่ความกว้าง 320px และเมื่อขยายตัวอักษร 200% เนื้อหา/ปุ่มไม่ทับกันหรือถูกตัด
- บนมือถือไม่ใช้ตารางที่ต้องเลื่อนแนวนอนเป็นวิธีหลัก ให้ใช้แถว/การ์ดที่มีลำดับข้อมูลเดิม

## ข้อกำหนดก่อนลงมือปรับ UI

เอกสารนี้เป็นข้อเสนอ UX/UI สำหรับตรวจทานก่อน implementation โดยเฉพาะรูปแบบเมนูหน้าแรก ข้อความปุ่มกลับ และผลของการลบครัวเรือน หากได้รับการยืนยันแล้วจึงนำไปปรับ Angular/Tailwind
